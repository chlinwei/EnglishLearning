## 词汇讲解：blanket（真实工作句子，非素材库）

- 用户贴出句子：`No blanket cache flush. Each batch needs the same app and resolver checks.`（运维流程/变更审核场景），问 `blanket` 怎么理解，并强调**别改文件**。
- 结论：`blanket` 作定语 = **一刀切 / 不分对象地覆盖全部**。`blanket cache flush` = 一次动作把缓存整个清光（作用于所有服务），与 `targeted / scoped / per-service / granular flush` 相对。
- 给的同族：`blanket ban` / `blanket rule`（一刀切规则）/ `blanket approval`（一揽子批准）/ `blanket statement`（一概而论的说法）；反义：`targeted` / `surgical` / `granular` / `across the board`。
- 语义路径：名词「毯子」（一盖盖住整片）→ 形容词「覆盖全体、不加区分」。中文最贴的对应：一刀切 / 一锅端 / 打包式。
- 句子的言外之意：全量清缓存会**擦掉现场**（清完就通了，但不知道是哪个环节的问题），还可能引发全局缓存同时失效；所以要逐批在未清状态下跑同一套 app + resolver 检查，才留得下可定位的证据。
- 发音提示：`/ˈblæŋkɪt/`，重音在 **-BLAN-**，ng 读 /ŋ/ 不拆成 n+k；印度同事易读成 /ˈblænkɪt/。
- 未改任何内容文件（用户明确要求）。

## 词汇讲解：holding（事故通报措辞）

- 用户贴出拟发给 Support 团队的通报：`Support needs an update. Can I say checkout is recovered and the mitigation is holding?` 问 `holding` 什么意思。
- `mitigation is holding` = **缓解措施撑住了 / 顶得住**，还没垮。`hold` 不及物，**主语是措施或状态本身**（不是人），核心义「承受压力而不失效」。
- 三态对照：`held`（复盘时回看，已撑住 N 分钟）· `is holding`（此刻仍在撑，未定论 → 实时通报最稳）· `isn't holding`（又坏了）。
- 同族：`hold up`（经得起检验）/ `hold off`（推迟）/ `hold on`（等一下）/ `rates holding steady`（保持平稳）。
- 顺手校准了用户的句子：`checkout is recovered` 略生硬，母语者多说 `has recovered` / `is back up` / `is recovering`；`the mitigation is holding` 完全地道，建议加 `so far` 并给观察窗（"monitoring for another 30 minutes before we call it"）。
- 发音：`/ˈhəʊldɪŋ/`，印度英语 /oʊ/ 偏 /oː/，-ing 快读接近 /in/。

## 词汇讲解：stated（with + 宾语 + 过去分词）

- 用户贴出：`Yes, with the monitoring period stated. Don't say both resolvers are repaired.` 问 `stated` 什么意思。
- `state` (v.) = **正式地、明确地写出/说明**（不是随口说、不是暗示）。`stated` 是过去分词，此处 = 「已被明文写明的」。
- 结构考点：**`with + 名词 + 过去分词`**（with 复合结构），表伴生条件/前提。「在把观察时段写清楚的前提下」。同族句式：`with the risk documented` / `with the tests passing` / `with the timeline attached`。
- 语义强度梯度（讲解给了图）：`say` < `mention` < `note` < `state` < `specify` / `spell out`。用户原句用 `stated` 而非 `mentioned`，就是要「落在文字上」这一层。
- 固定搭配：`as stated above` / `unless otherwise stated` / `the stated purpose`（号称的目的，常带质疑）/ `at the stated time` / `the stated SLA`。
- 用户原句后半句的信息：**措辞纪律 —— 不要把 mitigation 说成 repair**。`repaired` 意味着根因已除、永久修复；实际只做了缓解，应该用 `mitigated` / `worked around` / `we have a fix in place`。这条对 DevOps 事故通报是硬要求。
- 发音：`/ˈsteɪtɪd/`，-ed 因 t 结尾读 /ɪd/，印度英语把尾音节读得更完整（"stē-ted"）。

## 句子翻译：set out his stated rate and coverage

- 用户贴出 `he exchange set out his stated rate and coverage` 要求翻译。判断 `he` 是 `the` 的笔误，`his` 可能应为 `its`（若主语是交易所）。
- 主译：**交易所列明了它标明的费率与覆盖范围。**
- 关键词拆解：`set out` = 逐条列出、展开陈述（比 `state` 更强调「一条条摆出来」，合同/条款高频）；`stated` = 明文写明的（承接 10-14 上一条，这里是**定语**用法 `stated rate`，不是后置分词）；`rate` = 费率/利率，技术语境可指速率；`coverage` = 覆盖范围 / 承保范围 / 覆盖率（DevOps 语境多指监控覆盖或测试覆盖）。
- `stated rate` 是金融固定术语 = 名义利率 / 明示利率（与 `effective rate` 相对）。
- 两种语境译法已分别给出（金融合约 / 技术监控），请用户确认。

## 词汇讲解：establish（CNN01-03）

- 用户贴 CNN01-03 整段问 `establish` 的意思。
- 原句：`It did not establish that a particular trade outcome was inevitable.` = 报道并未**认定**某个贸易结果必然发生。
- `establish` 此处 = **认定 / 确证（证据足以支撑某个结论）**，不是「建立、设立」。结构：`establish that + 从句`；否定式常用来表示「（材料）不足以支持这个结论」。
- 证据强度阶梯（配图）：`suggest` < `indicate` < `show` < `confirm` < `establish` < `prove`。
- 其他高频义项：`establish a company`（设立）/ `establish contact`（建立联系）/ `establish a reputation`（树立声誉）/ `establish the facts`（查明事实）/ `established` & `well-established`（公认的、既定的）；法律语境 `establish liability`（认定责任）、`fail to establish`（未能证明）。
- 这段的划界链条：`presented as` · `raised the possibility` · `might lead` · `did not establish … inevitable` —— 整段都在弱化断言，establish 是其中语气最硬的一个否定。
- 发音：`/ɪˈstæblɪʃ/`，重音在第二音节 **-STAB-**；词内 `st` 接近 /sd/，印度英语 /æ/ 偏 /a/。
