## 🔧 深挖并修复 git push 卡死（根因定位）
- 现象：`git push` 永久挂起；但 `git fetch` / `ls-remote` 正常，`curl` 访问 GitHub 也正常。
- 排查过程：
  1. 排除网络（`github.com:443` 0.5 秒返回 200）
  2. 发现 `git-credential-manager get --no-ui` 能取到凭据，而 `git credential fill` 会超时
  3. `GIT_TRACE=1` 抓到了完整链路
- **根因**：WorkBuddy 自带 PortableGit 的**系统级** gitconfig 里配置了
  `credential.helper = helper-selector`（`git-credential-helper-selector`，一个弹窗选择器）。
  GitHub 返回 `401 Unauthorized` 后，git 调用该选择器，它弹窗等人点击 → 无响应 → 无限等待。
  git 会按顺序尝试所有 helper，因此即使全局已配了 GCM 也没用。
- **修复**：在全局 `~/.gitconfig` 用空值重置 helper 列表以顶掉系统级配置：
  ```
  git config --global --unset-all credential.helper
  git config --global --add credential.helper ""
  git config --global --add credential.helper '!f() { git-credential-manager "$@" --no-ui; }; f'
  ```
- 修复后 `git push` 秒回 `Everything up-to-date`，退出码 0。
- 经验：这类「凭据卡死」问题，`GIT_TRACE=1` 一抓就现原形，比反复试参数有效得多。
